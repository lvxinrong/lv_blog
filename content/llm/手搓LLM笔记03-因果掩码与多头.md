> 系列规则不变：写下来的必须是自己搞懂的。但这一篇要破例一次——第三章（因果掩码 + 多头注意力）我自认只懂了八成，所以这篇除了笔记，也如实记录我"还没通"的地方。它是我回炉时的地图。

## 一、因果掩码：防的不是过拟合，是答案泄露

训练时，模型是一次性看到整句话的。如果不加掩码，预测下一个 token 时，答案就躺在输入里——模型只要学会"看下一个位置"照抄，loss 瞬间归零，**什么都没学到**。

我一开始把这理解成"过拟合"，Kimi 纠正了我：这比过拟合直接得多——**是考试作弊**。题目和答案同时发下来，考满分也没有意义。因果掩码保的不是防过拟合，是**保证"预测下一个 token"这个任务本身有意义**。

推理时不需要掩码：自回归生成时未来还没生成，天然看不到。所以掩码纯粹是为训练准备的——**让训练时的看题条件和推理时保持一致**。

## 二、实现：负无穷，不是 0

掩码的形状：一个上三角矩阵，第 i 行只允许看第 i 列及左边（位置 i 只能见到 ≤ i 的历史）。"床前明月光"五步展开：床 / 床前 / 床前明 / 床前明月 / 床前明月光。

我踩过的坑：**掩码位置为什么不能填 0？** 因为 softmax 里 e⁰ = 1——填 0 的话，这些被掩盖的位置照样参与归一化，稀释别人的概率。所以填**负无穷**：e^-∞ = 0，从归一化里彻底除名，反向传播时梯度也恰好为 0，从计算图里干净地消失。

书里其实演进过两版：先 softmax 再掩盖再重新归一化（能跑，但多算一次归一化）；后来改成 softmax 之前填负无穷（一次归一化搞定）。主流全用后者——更省，也更干净。

## 三、多头：加的是视角，不是角色

3.6 节我花了一整天。

**形状**：d_out = 768、8 个头，每个头处理 768/8 = 96 维。

**W_q 是共享还是独立？** 这里有个障眼法：代码里 `W_q` 表面上是 class 的一个属性、一块平面矩阵 (d_in, d_out)，看起来共享——但实际上是**把 8 个 (d_in, 96) 的小矩阵按列打包在一起**。第 0~95 列服务头 1，第 96~191 列服务头 2……逻辑上独立，物理上合并，为的是让 GPU 一次矩阵乘搞定 8 个头，而不是循环 8 次。

还有一个容易记岔的细节：**权重本身没有"头"这个维度**。头维度是投影之后，把输出 (B, T, 768) reshape 成 (B, T, 8, 96) 再 transpose 出来的——**多头维度是电流流过时折出来的，不是电阻上的刻痕**。

这也对上我第二章笔记里的那条：**切 token 是事故，切维度是设计**。

## 四、合并：拼接是摆回去，W_o 才是搅在一起

每个头算完自己的注意力，得到 (T, 96)。然后两步：

1. **concat**：8 段 96 维首尾相接，摆回 (T, 768)——纯机械的形状操作，**摆在一起，但互没说话**；
2. **输出投影 W_o (768, 768)**：做一次矩阵乘。`C[i][j] = Σ_k A[i][k] · B[k][j]`——输出的每一维都是全部 768 维的加权和。**头 1 的结果和头 8 的结果，在这一步才真正乘进同一个维度里。**

所以：拼接负责"摆回去"，W_o 负责"搅在一起"。头与头的信息交互，发生在 W_o，不在 concat。

## 五、回答我自己留下的问题

笔记 02 结尾我留了个问题：**Q、K、V 真的够吗，投影会不会越多越好？**

读完多头，答案清楚了：

- **三个角色是最小完备集**——我去找（Q）、我被找（K）、我交货（V），少一个就塌方，多一个没槽位。角色表是满的；
- **但"更多投影"以另一种方式兑现了**——不是加第四个角色，而是把 Q、K、V 整套**复制 h 份**，每个头看一个角度。多头就是"更多投影"的正确打开方式：不加角色，加视角；
- 行业后来甚至反向操作：GQA/MQA 让多个头共享 K、V 省显存，DeepSeek 的 MLA 把 K、V 压成低秩矩阵。角色不动摇，头数、共享、压缩随便玩。
