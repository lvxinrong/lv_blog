## 公共阅读骨架

每个家族后续都按实际源码情况选择以下模块，不要求全读：

- config、Tokenizer、Chat Template；
- Embedding 与位置编码；
- Attention、QKV、Head、KV Cache；
- Norm 与残差结构；
- Dense FFN 或 MoE；
- 顶层 forward 与权重加载；
- Generation、Decode 与 Cache 状态；
- 量化、稀疏、压缩、MTP 等特有机制；
- 推理部署与 Kernel 接口。

## 证据要求

每篇正式专题未来至少保留：

- 官方模型卡、官方仓库与固定 tag / commit；
- config 字段 → 源码类 / 初始化参数 → 权重 key 的对应关系；
- forward 和 cache decode 的关键张量流；
- 已确认事实、结构推断、官方明确设计意图和待核实项的区分；
- 条件允许时，一个最小实现、最小探针或受控官方对照。

不用“官方 config 写了”直接推出训练资源、质量或性能结论。

## 横向比较协议（未来专题方向，不新建空文章）

- GQA / MQA / MLA / SWA / 稀疏注意力：分别压缩什么，付出什么代价；
- Dense FFN / MoE：总参数、激活参数、路由与负载均衡；
- RoPE / Partial RoPE / YaRN：位置表示与上下文扩展；
- KV Cache：全量、低秩、跨层复用与稀疏索引；
- Engram：额外记忆如何进入模型；
- MTP / DSpark / 普通投机解码：草稿、验证与缓存回滚；
- 量化与部署：权重存储、激活精度、显存、带宽和 Kernel 支持；
- 不同资源约束下，哪些压缩可以放松，哪些稀疏机制仍值得保留。

横向比较必须区分四类证据：官方明确说明的设计动机；config / 源码可确认的结构事实；个人推断；真实实验结果。
