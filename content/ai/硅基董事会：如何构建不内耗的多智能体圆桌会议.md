> 分歧是圆桌的产物，不是圆桌的故障。
>
> 这是一份架构推演，不是已建成系统的验收报告。文中没有实验数字，因为实验还没做。

## 缘起：一个脑暴搭子，不够用了

在[《我的脑暴搭子不是人》](/ai/ai-brainstorm-buddy/)里我写过：一个人脑暴的死因是存量见底，想着想着就没有输入了。一个 AI 搭子解决了输入问题，但它只有一个回声——它的盲区就是我的盲区，它的偏好就是我的偏好。

我现在同时用着几家不同厂商的模型，各有各的能力上限和思考强度：有的数学强，有的中文语境熟，有的长上下文稳。一个自然的想法是：别一个一个聊了，让他们开会。

但“把几个 Agent 拉进一个群”是最容易想到的方案，也是最容易死的方案。死法有三种：

**回音室。** 所有发言互相可见，A 说完 B 附和，C 在 A 和 B 的基础上“补充”，三轮之后所有 Agent 收敛到同一个腔调，互相吹捧，分歧消失。这不是模型变笨了，是输入被污染了。

**上下文爆炸。** 全量广播意味着每个 Agent 每轮都要读其他所有 Agent 的全文，N 个参会者，信息量按 N 的平方涨。会开到第三轮，窗口先满了。

**结论难产。** 要么没人负责收敛，讨论无限发散；要么某个强势 Agent 越权拍板，把圆桌变成一言堂。

三个死法指向同一个根因：**内耗不是模型问题，是拓扑和职责问题。** 模型够聪明了，缺的是会议制度。下面是我设计的一份制度，先给原始草图，再逐条拆。

## 原始设计草图

以下是我的原话，一字未改，作为这份架构的灵魂：

> 主持人接收来自我的想法，因为想法会比较粗，先和主持人沟通清楚。然后由主持人发起圆桌会议。其他参会Agent依次发言，然后主持人接收所有信息后进行压缩和摘要。然后形成第二轮讨论的方向和第一轮的结论。并指出圆桌中某些Agent过于偏离，甚至幻觉。多轮讨论之后，主持人就可以收官。但是这个收官是可以交由一旁的记录员来做，记录员可以看到所有的对话内容，和每轮主持人的摘要。最后生成的结论，发到圆桌会议中，由各个Agent + 主持人来进行打分，共同决策是否可以形成结论，并交付。
>
> 上下文爆炸只会发生在主持人和记录员上，这里可以再拆分开，比如多主持人，一主两从的方式。记忆结构也可以借鉴cowAgent的多层记忆框架。
>
> 角色同化我不担心，因为整个圆桌会议中，所有参会人员只和主持人交流，其他讨论人员之间的思路是互相不可见的。
>
> 主持人是小圆桌，互相之间的记录都可见。大圆桌是参会，独立发言。而且主持人不需要判断正确与否，只需要专注整理，找差异，总结，再次交流。
>
> 然后根据模型的思考强度，能力上限，给权重，这个权重也是动态的，比如某个领域，假如数学，就多听gpt的发言，给gpt的发言高权重。涉及国内的，就给国内模型高权重。

拆成四个设计：拓扑、主持人、权重、记忆。

## 设计一：大小圆桌，星型拓扑

**大圆桌独立发言，小圆桌共享记录。** 这是整份设计的地基。

大圆桌是参会 Agent 的会议。规则只有一条：所有参会人员只和主持人交流，其他讨论人员之间的思路互相不可见。拓扑上这是一张星型网——所有边都经过中心节点，参会者之间没有直连。

小圆桌是主持人之间的会议。一主两从，互相之间的记录全部可见。因为压缩者之间必须共享上下文，才能对齐摘要口径。

为什么这能解决角色同化？回到第一性原理：**回音室的成因是输入污染。** A 看到 B 的发言之后，A 下一轮的采样条件里就混入了 B 的分布；多轮迭代，所有 Agent 的条件分布互相收敛，腔调趋同，分歧被磨平。靠提示词写一句“请保持独立思考”对抗不了这件事——污染在上下文里，不在指令里。

星型拓扑从采样条件上切断了污染：每个 Agent 每轮看到的只有议题、主持人的摘要和定向转述，看不到同伴的原文。独立性不是被要求出来的，是被结构保证的。分布式系统里这叫 shared-nothing；会议制度里这有个更老的名字——德尔菲法，专家背对背多轮作答，几十年前就在用。我不发明方法，只是把它工程化。

独立发言还有一个副产品：**分歧变得可测量。** 同一个问题收到 N 份独立答案，哪些一致、哪些冲突、谁和谁差得最远，是一张清晰的差异矩阵。这张矩阵就是主持人下一轮的原料。群聊式讨论里，分歧在附和声中早就没了，你连测量的对象都没有。

一句边界说明：拓扑隔离切断的是会议内的互相污染。模型出厂自带的相似偏好——相近的训练数据、相近的对齐口味——它管不了，那要靠异构厂商选型来缓解。所以“角色同化我不担心”的完整表述是：会议内的同化我不担心，会议外的同源趋同，靠异构选型另行处理。

## 设计二：主持人是压缩器，不是法官

主持人的职责清单：

- 接收我的粗想法，先沟通清楚，再发起圆桌；
- 每轮收齐所有发言，压缩、摘要，形成第一轮结论和第二轮方向；
- 指出某些 Agent 过于偏离，甚至疑似幻觉；
- 多轮之后收官——收官可以交给记录员。

清单里最关键的一条是否定句：**主持人不需要判断正确与否，只专注整理、找差异、总结、再次交流。**

为什么不让主持人判对错？三个理由。

**判断需要领域能力。** 主持人一旦下场判决，圆桌结论的上限就被钉死在主持人的能力上限上，其他参会模型再强也只是摆设。你请了一桌专家，最后由秘书拍板，这是组织设计的事故。

**判决权集中会引入单点偏见。** 主持人也是模型，也有自己的偏好和盲区。让它当法官，等于把单模型的偏见放大成整个圆桌的结论。

**主持人的价值在信息处理，不在知识。** 整理、找差异、总结、再交流——这些是长上下文与摘要能力，不是领域知识。分工上，判断权留给最后的加权打分环节，那里才有各领域的专家。

那“指出偏离甚至幻觉”和“不判断对错”矛盾吗？不矛盾，这是两个层级：**标记是元信息，判决是结论。** “某 Agent 偏离议题”是相关性标注；“疑似幻觉”是带证据引用的存疑标记，不是终审。标记交给后续轮次去质询、交给打分环节去裁决。主持人是路由器加压缩器，不是法官。

交叉质询怎么发生？靠**代理转述**。A 的论点由主持人转述进 B 的下一轮输入，B 反驳的是“主持人转述的 A”，不是 A 本人。质询发生了，隔离没有破。主持人像网络里的代理节点：两侧都只看得见它，看不见对方。

这个克制还有一个工程红利：主持人不需要最贵的模型。它要的是稳定的长上下文和可靠的摘要，一个中档模型就能胜任。圆桌的成本大头留给参会专家，主持人便宜一点，成本结构才好看。

## 设计三：动态权重，推理时的 MoE

收官不是一锤定音。记录员生成的结论草案发回圆桌，由各个 Agent 加主持人一起打分，共同决策能否形成结论、是否交付。

打分不是简单多数，是**按领域动态加权**：

- 议题是数学，就多听 GPT 的发言，给它高权重；
- 议题涉及国内语境，就给国内模型高权重。

权重的依据是模型的思考强度、能力上限和领域履历，而且随议题流动，不是一张写死的表。

这本质上是 MoE 的思想搬到了推理编排层：MoE 的路由器按 token 选专家，圆桌的路由器按议题域选投票权重。专家还是那些专家，变的是谁的话更算数。

但类比要守住边界，不神似过头：**MoE 的路由是训练出来的，圆桌的路由是配置加履历统计。** 前者是学出来的参数，后者是可审计的规则。我不假装这里有一个可微的路由器——它是推理时的显式路由，权重表要落盘、可复现、可审计。否则“动态权重”会退化成“主持人拍脑袋”，那比固定权重更糟。

打分环节还有一条纪律：**反对意见写进交付物，而不是被投票消灭。** 加权共识决定“是否交付”，不决定“反对者闭嘴”。结论附上分歧记录，交付的人才知道这个结论的置信边界在哪。

## 设计四：上下文爆炸与记忆分层

全量信息只汇聚在两个角色身上：主持人和记录员。参会 Agent 的上下文是有界的——议题、摘要、定向转述，没了。所以爆炸风险被拓扑收敛到了两个点，可以逐个拆。

**主持人侧：一主两从。** 从主持人分片压缩，比如按议题分、按参会 Agent 分组；主主持人汇总对齐。小圆桌共享记录保证三个压缩者口径一致。这是把单点的上下文压力拆成可水平扩展的压缩集群——压缩也是可以分片的。

**记录员侧：独立收官。** 记录员看得到所有对话内容和每轮主持人摘要，收官草案由它执笔。为什么收官不留在主持人手里？因为主持人全程在做有损压缩，每轮摘要都在丢信息；记录员持有无损日志，收官时能回到原文核对。**压缩误差不能累积成结论误差**，这是记录员存在的理由。

记忆结构借鉴 CowAgent 的多层框架。我在 Mac mini 上跑着它，它的分层是现成的参考答案：

- 核心记忆不随时间衰减，日常记忆按天滚动、带半衰期，蒸馏日记做定期沉淀，知识库按主题组织成 wiki；
- 检索分两条路：混合检索（关键词加向量）负责找，整文件读取负责取——大文件必须先分片，否则一次读入就顶爆上下文；
- 上下文超限时自动裁剪最旧一半，并把摘要写进日常记忆。

映射到圆桌：圆桌宪法和角色契约是核心记忆，永不衰减；每轮摘要是日常记忆，按轮次滚动；收官蒸馏是蒸馏日记；历史结论库是 knowledge，供后续会议检索引用。

最后一条最值得抄：**压缩是设计内的职责，不是事故处理。** 上下文满了才想起来摘要，那是被动挨打；每轮强制压缩落盘，那是主动管理。CowAgent 把裁剪和摘要做成了自动机制，圆桌把压缩做成了主持人的本职。

## 工程实现：一台有限状态机

制度要落地，得变成状态机。整场会议是一台 FSM：

```text
INTAKE   想法澄清：主持人和我把粗想法聊成明确议题
OPEN     发起圆桌：议题、参会名单、领域权重表落盘
COLLECT  独立发言：各 Agent 背对背提交结构化发言
COMPRESS 压缩摘要：共识、分歧、偏离标记、下一轮问题
CROSS    代理转述：把分歧定向转给相关 Agent 质询（可选）
CLOSE    记录员收官：基于全量日志和每轮摘要写结论草案
VOTE     加权打分：各 Agent + 主持人按领域权重评分
DELIVER  交付：结论 + 分歧记录 + 权重表归档
```

转移规则：COMPRESS 之后判断收敛——分歧收口或达到轮次上限，进 CLOSE；否则带着第二轮方向回 COLLECT。VOTE 未达阈值，带修改意见回 OPEN，重开一轮。

每个状态的输入输出都是契约，消息有 schema：

- 发言：立场、论据、置信度；
- 摘要：共识、分歧、偏离标记、下一轮问题；
- 打分：分数、理由、领域标签。

架构师视角看，这台状态机有三个工程性质值得强调：

**会议日志是 append-only 的事件流。** 所有发言、摘要、打分只追加不修改。任何角色——主持人、记录员、事后审计——都能从日志重建现场。这是 event sourcing，会议只是它的一个投影。

**每轮摘要就是 checkpoint。** 进程崩了、窗口爆了，从最近一轮摘要恢复，不用从头开会。压缩的副产品是可恢复性。

**轮次上限和打分阈值是熔断。** 讨论不允许无限发散，交付不允许无限重开。圆桌要有散会的纪律，否则它只是昂贵的闲聊。

再说一次边界：这是设计推演，系统还没有实现，上面没有任何实验数字。状态机画得出来，不等于会开得好——那要等真跑起来才知道。

## 尾声：先立 Flag，再死磕 Infra

这份圆桌设计，是我 I6 之后的重要探索方向。

眼下的节奏不变：I6 领域后训练打榜是眼前的主线，再往后是第三阶段 S0 到 S6——性能基线、推理引擎、算子、分布式、生产 Serving，一关一关死磕大模型 Infra 基础。roadmap 的第六阶段本来就叫“Agent 与多模型协作”，圆桌是那条远期线上的事，现在只立 Flag，不排期。

顺序不能反。没有单模型能力的底子，圆桌只是把幻觉开会放大；没有 Infra 的底子，一主两从的压缩集群连部署都成问题。**先让每个模型值得被听见，再设计怎么听。**

董事会的价值，从来不是让每个董事更聪明，而是让聪明不被内耗吃掉。
